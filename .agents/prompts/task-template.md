# 任务派发常驻模板（Task Dispatch Template）

> **用法**：给 AI 派发复杂代码需求时，二选一——
> ① 将需求粘贴到下方【具体需求描述】占位处，把整份规范一并发出；
> ② 直接指示 AI：读取 `.agents/prompts/task-template.md`，并严格遵循其中【执行与交付硬性规范】。
>
> updated: 2026-09-15（基于 2026-09 模板评审修订：补测试失败出口、条件化落点确认、注释标签映射表、靶心数量弹性）

---

## 任务派发 Prompt

【具体需求描述】
`<在此处粘贴/说明你的具体代码需求>`

---

【执行与交付硬性规范】

0. 落点先行：涉及对外契约改动 / 跨文件大面积改动 / 需求有歧义时，
   先给落点方案等确认再动手；单文件小改一句话带过落点后直接完成。

1. 规范锚定：代码规范遵循 `stock-calculator-backend-dev`，流程护栏遵循 `dev-loop`；
   验证命令优先查 dev-guide §3 命令速查。

2. 注释分级：
   - 禁止为显而易见的业务分支 / Getter/Setter / 样板代码添加注释；
   - 必标区（函数或代码块上方）：高并发锁与事务边界 → `[Critical Area]`；
     数据契约（DB 生成列 / JSONB 映射 / Modulith 边界）→ `[Contract]`；
     隐蔽 Edge Case → `[Edge Case]`。Entity 字段级契约注释属必留项；
   - 改动触达已标记区域时，复核标记是否仍适用，过期即更新或移除。

3. 交付验证：业务代码改动必须跑测试（全量 `./mvnw install -Dtest='!TaskServiceTest'`）；
   跑不通时如实报告失败命令与错误，严禁删测试 / 改断言粉饰。

4. 靶心汇报：回复最末尾附 [核心审查区] 块——过滤 Import / 格式化 / 样板代码，
   默认 1~3 处（大需求可放宽至 5，纯样板改动写"无高危区"），每处一行，格式：

### [核心审查区]
* `文件路径:行号` -> `1句核心改动与高危原因说明（触发条件 + 影响面，非改动复述）`
