# Agent 编排 · 可能性功能展望

> orchestration 框架落地后**可以被规划出来的能力清单**。原则：能力加法做在工具注册
> （新 @Tool 或 main 接口登记），不改编排器、不写死任务链。
> 框架设计见 [agent-orchestration](agent-orchestration.md)。

## 一、首发场景（驱动第一期落地）

### 1.0 定时提醒（简单意图快路径的代表）

> 用户：「明天 9:30 通知我茅台的形态」

规划产物是**微小 DAG**（触发 → 调 mcp 经纪人 → 通知触达，1-3 节点），走 Planner 快路径
（免向量匹配、套模板直出）。各 MCP 服务按职责被组装：mcp=经纪人、通知=触达出口——
服务不关心流程长短（D12），这是「同一引擎覆盖简单与复杂」的首发验证场景。

### 1.1 公告订阅 + 形态分析（端到端首条链路）

> 用户：「有最新公告出台的时候告诉我，顺便看看茅台现在的形态」

预期 DAG 形态（由规划 agent 生成，示意）：

```
[查最新公告摘要]（rest → main announcement）
     ↓ depends_on
[等公告出台]（mq_wait，挂起至事件唤醒）
     ↓
[算形态]（mcp → stock_analysis / stock_levels，参数 $stockId）
     ↓
[汇总写回 + 完成事件] → copilot SSE 推送用户
```

价值：验证 mq_wait 长时挂起、跨服务工具组合、复用缓存全链路。

### 1.2 知识印证型问答

> 用户：「KDJ 金叉什么意思，原书怎么讲？茅台现在出现金叉了吗？」

组合 `kb_search`（原书出处）+ `stock_analysis`（实时指标），单轮内即时完成——
这条链路验证「一次规划内多工具并行 + 结果合并」。

## 二、后续可能性（按工具就绪度分组）

### 2.1 行情/指标深水区（mcp 工具微扩即可）

| 功能 | 用户说法示例 | 需要的新工具 |
|---|---|---|
| 多股对比 | 「茅台和五粮液近一个月哪个更强」 | 复用 stock_daily，DAG 内并行两节点 + 汇总节点（汇总可用 LLM 收尾） |
| 自选股体检 | 「把我自选股全过一遍，有跌破支撑的告诉我」 | rest 读自选列表 → DAG 对每只并行 stock_levels → 过滤/汇总 |
| 板块联动初探 | 「消费类最近有什么异动」 | 需 mcp 增板块成分/涨跌工具（路线二全市场数据的子集） |

### 2.2 信息管道类（主要组合 main 接口 + MQ）

| 功能 | 用户说法示例 | 依赖 |
|---|---|---|
| 关键词雷达 | 「以后凡是提到'以旧换新'的公告/联播内容都推给我」 | 意图规范化把「以后凡是…都」识别为订阅型；mq_wait 挂 kg/announcement 事件 |
| 联播要闻跟踪 | 「新闻联播提到新能源时给我时间线脉络」 | kg 域时间线接口登记进 registry + 订阅事件 |
| 摘要日报 | 「每天早上给我昨天全部订阅内容的摘要汇总」 | 定时触发型 DAG（触发器= cron 语义节点，需扩 executor 触发类型） |

### 2.3 MQ 可观测与运维自愈（mq/ 子包工具的消费方）

| 功能 | 用户说法示例 | 依赖 |
|---|---|---|
| 管道问诊 | 「我的公告摘要怎么还没来？」 | copilot 调 task_trace / queue_stats 定位卡点，人话回答 |
| 死信人工介入 | 「死信里有什么？把能重投的投回去」 | message_peek + message_requeue（high risk，仅人工对话触发，不进规划集） |
| 压测/演练 | 「往测试交换机发 10 条模拟公告消息」 | message_publish（白名单交换机 + 数量上限） |

### 2.4 进阶（远期，评审后再立项）

| 功能 | 说明 | 前置条件 |
|---|---|---|
| plan 演进 | 工具升级后对存量 verified plan 自动重规划候选 | registry 变更扫描 + 版本对比 |
| 多用户订阅收敛 | 同一意图多用户订阅 → DAG 实例合并、结果分扇出 | task_instance 增加 fan-out 语义 |
| 主动建议 | copilot 基于历史任务提议新订阅（「要不要我盯着…」） | 复用统计（use_count）+ 用户画像 |
| 全市场选股 | 「每天筛出 KDJ 低位金叉且放量的小盘股」 | 路线二全市场日线落库（mcp design §七 独立 epic） |

## 三、明确不做（边界）

- **高危写操作自动化**：sync 域用户数据、auth 域、删库类接口永不登记；
- **DAG 内嵌脚本**：复杂转换回归「写一个新工具」，不扩展表达式引擎；
- **执行期 LLM 自由决策**：agent 只在规划期与收尾汇总出场，执行链路零 LLM（廉价校验除外）；
- **通道即状态**：MQ 队列只做传输资源，权威状态永远在 PG。
