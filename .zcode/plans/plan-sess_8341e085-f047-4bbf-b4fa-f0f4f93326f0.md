# data 模块多副本改造 v4：单一 worker 变体，多机共同消费

**目标形态**：主机 1 跑 all-in-one（零改动）；新增**一个** worker-only 变体镜像， collector/ingest 关闭、worker 两域（公告蒸馏 + 向量化）全开——同一镜像部署到多台服务器，每副本用自己的 env（各自的 CF/LLM key），竞争消费同一组 quorum 队列。不做域级拆分。

## A. 硬阻塞修复：CninfoClient 跨角色依赖（不改这个，worker 变体构建即失败）

1. `AnnouncementProcessWorker`（worker 门控）注入的 `CninfoClient` 目前只由 `CollectorConfig`（collector 门控）注册，类注释"worker 部署无需本类"已过时（downloadPdf 随 worker 处理链迁入但 bean 没跟上）。
2. 修复：新增 worker 自持的 `CninfoPdfClient`（UA、STATIC_BASE、PDF magic 校验、throttle 随迁，配置走 worker 侧 props）；worker 改注入它；collector 的 `CninfoClient` 移除 downloadPdf 并修正注释；同步修相关测试。

## B. 构建变体（2 个镜像）

| VARIANT | 镜像 | 角色 | 构建期钉死 |
|---|---|---|---|
| `all`（默认，现状） | `…-data` | collector+worker+ingest | 全开（现状不变） |
| `worker` | `…-data-worker` | 仅 worker 两域全开 | collector/ingest=false + spring.main.web-application-type=none（否则 Tomcat 照启——starter-web 无条件依赖） |

- build-native.sh：`VARIANT` env（默认 all）+ `BINARY_NAME` 变量贯穿 native-image `-o` / objcopy 剥离 / 冒烟调用；worker 变体 dummy 凭据带 CF+LLM 两套（构建期 fail-fast 需要）。
- smoke-native.sh：worker 变体二进制路径带 `-worker`，只做 `Started DataServiceApplication` 日志断言（无 HTTP 可探），保留超时与清理逻辑。

## C. 每副本不同 key：纯配置，无代码改动

- key 是运行期值非 AOT 条件：每容器 env 各配 `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL`、`CLOUDFLARE_ACCOUNT_ID/CLOUDFLARE_API_TOKEN`（同机多副本不同 key 用多个 env 文件或 `podman run --env-file`）。
- `EmbeddingRateLimiter` 每实例生效 → key 不同则限速天然独立。

## D. 存活探针（回应评审第 1 点）

1. **应用层 watchdog**（无条件组件，两变体都带）：独立单线程 executor（不占共享调度池）；每 60s（`datasvc.heartbeat.interval-ms`）经 RabbitTemplate 对已知队列 passive declare 往返（10s 超时，防半开 TCP 挂死）；成功 → 原子 touch `/tmp/datasvc-heartbeat`；连续 3 次失败（可配）→ log.error + System.exit → `restart: unless-stopped` 真正自愈。覆盖死锁/假死/连接静默断开。
2. **Dockerfile.worker**（`ARG BINARY_NAME` 参数化）：HEALTHCHECK = 心跳文件新鲜度 shell 检查（date/stat，无 curl）。分工写进文档：HEALTHCHECK=可见性，watchdog 退出=自愈。

## E. 部署面

3. **docker-compose.yml**：`data-worker` service 挂 profile `data-worker`（主机 1 默认不激活）；**mem_limit: 2g**（注释含并发 × PDF RSS 峰值估算）；无 ports；env_file: .env。
4. **CI**：新增 `build-data-worker` job（同 data path filter、同 GraalVM 步骤、并行），build-args 传 BINARY_NAME，镜像 `…-data-worker`、缓存独立 scope。objcopy 剥离（已入库）对两变体生效。
5. **runbook `docs/data-worker-replica-deploy.md`**：
   - 传输已定：虚拟网 overlay，`RABBIT_HOST` 填主机 1 虚拟网地址，AMQP 明文跑 overlay 内不加 TLS，compose 5672 无需改，主机 1 防火墙放行 overlay 网段；
   - **AOT 裁剪边界矩阵**（评审第 2 点）：worker 变体中 collector.*/ingest.* 已编译期裁剪，运行期 env 强开无效；all-in-one 中角色运行期也关不掉；
   - **幂等与自包含结论**（评审第 3 点，已核实）：任务载荷自包含（announcementId/adjunctUrl/title，worker 自下载 PDF，进程内 pdfCache，临时文件不出消息生命周期），无共享文件系统依赖；主服务结果摄取幂等护栏已在（FAILED 终态不回退、非 PENDING 回报忽略、DONE 判重）；重投递的重复 LLM 开销是 D6 at-least-once 既有语义窗口，多副本不破坏正确性，后续可选发布端 in-flight 标记加固；
   - history-sync 只由 all-in-one 消费（collector 门控），worker 副本不参与——对 CLS 礼貌限速语义，刻意为之；
   - D8 额度记账单账号口径、发布端 RATE_LIMITED 熔断全局生效两条保守行为说明。
6. 设计文档 §6 部署表补 worker 变体一行；公告 worker 并发旋钮（`datasvc.worker.prefetch.announcement-concurrency`，默认 1）保留在本次范围——主机 1 不换镜像即可先提并发。

## 验证
- `bash -n` 两个脚本；data 模块单测。
- 可行则本地跑一次 `VARIANT=worker` 构建（8~15 分钟）验证 CninfoClient 修复；CI 为最终门。
- 上线验收：LavinMQ 管理台 `task.announcement.process.q` / `task.embedding.compute.q` 消费者数 ≥2；两台机器日志各见任务消费；`podman ps` health healthy。

## 已定决策
1. 跨机传输 = 虚拟网 overlay，AMQP 不加 TLS。
2. 不做域级拆分；key 分配由你部署时写进各容器 env。
